# Solana engine dependencies

Reviewed against KDF [`b1ff8f05c880d6f118124cac9ef615aa9d91bb39`](https://github.com/GLEECBTC/kdf-internal/commit/b1ff8f05c880d6f118124cac9ef615aa9d91bb39), Solana integration PR [35](https://github.com/GLEECBTC/kdf-internal/pull/35). This is a development reference, not a replacement for the production engine. Keep this short record current when the combined candidate changes.

| Dependency | Current evidence and integration behavior | Evidence required to close |
|---|---|---|
| SPL withdrawal Max | The reviewed engine converts the human-readable spendable token balance to an integer before constructing raw token units. Fractional balances can become zero or lose decimal scaling. The wallet integrates Max but refuses it while `SOLANA_SPL_MAX_ENABLED=false`. Exact-amount classic SPL remains the development path. | On the combined engine, decode signed transfers for balances below one token, fractional balances such as `12.5`, and high-precision values. Verify raw units, reported amount, fee funding, and full-balance result for both derivation modes. A Dart fixture cannot establish this Rust fix. |
| Token-2022 transfer and rent | The reviewed transfer construction uses the classic SPL instruction path; account sizing assumes the classic account length. Program/mint/decimal types and fixtures exist, but public listing and sending stay disabled with `SOLANA_TOKEN_2022_ENABLED=false`. | Engine transfer construction must use the configured program and extension-aware account sizing. Test a supported-extension allowlist, associated-account creation, rent, wrong mint/program, destination account forms, and unsupported-extension rejection. Publish only reviewed assets. |
| Token history stream behavior | SDK subscribes once to the SOL platform and dispatches individual transaction objects by `coin`; balance stream payloads are arrays. Token-level streaming support is not assumed. Indexed history does not reliably include memo or execution status; those values remain absent. | Capture real platform events for incoming ATA transfers, outgoing SPL transfers, fee-only rows, version-0 transactions, pending-to-finalized reconciliation, reconnect, and deduplication. Verify event asset identity and case-sensitive signatures. Keep polling available. |
| Late-token history backfill | The platform history loop can advance before a newly activated token is known. SDK later-token activation, targetless v2 fetching, and cache restart are integrated; replayed cached history is not proof of engine backfill. | Activate SOL first, receive SPL before enabling its token, enable it later, paginate and restart. Verify the prior token transaction appears exactly once in both native and browser history with the corrected engine. |

The development build workflow [40693119999](https://github.com/GLEECBTC/kdf-internal/actions/runs/40693119999) built the Solana head for WASM, iOS, Android arm64/armv7, macOS, Linux and Windows. Compilation and lockfile validation do not establish a passing full engine test run.

Release must use **one combined KDF commit** across all seven required platform artifacts. Preserve the production `f9632e0ec771668a6f21b37aede01a30110141cb` changes, including LI.FI, when combining Solana. The divergent `b1ff8f0` branch must not be substituted directly into production build configuration. Record the full commit and artifact digests, then repeat wallet and swap acceptance on that exact candidate. Solana mainnet atomic trading additionally requires the audited/deployed program, operational prerequisites, and removal of the KDF mainnet trading gate. Solana routed trading needs a separate upstream execution contract.

The native unfunded smoke in [SOLANA_INTEGRATION.md](SOLANA_INTEGRATION.md) supplies useful early activation evidence; it closes none of the funded withdrawal, history-backfill, or atomic recovery dependencies above.
