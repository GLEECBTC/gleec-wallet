# Measuring wallet load

Use three complementary measurements: replay tests isolate SDK behavior, a real
KDF process measures engine/network latency, and the browser measures the app's
main-thread work. [TESTING.md](TESTING.md) is the authoritative command map;
[tool/README.md](../tool/README.md) describes reusable diagnostics.

## Scorecard

Record authentication duration, activation duration, first fetched balance,
RPC counts, frame-arrival gaps, device/refresh rate and the exact wallet/SDK/KDF
revisions. Distinguish cached or synthetic balances from a post-activation fetch.
Compare equivalent wallet types, coin sets, address counts and network settings.
A replay result cannot establish real-network speed or browser responsiveness.

## Replay and process harnesses

`komodo_defi_harness` uses the real SDK with a replay RPC backend. Run both HD
and Iguana fixtures. Its benchmark writes `build/bench_result.json`; the retained
`tool/bench_baseline.json` and `tool/compare_bench.dart` implement the 30% gate.
Update a baseline only after investigating a reproducible intended change.

The process tier uses a real KDF and network. Supply an unfunded, disposable seed
through `KDF_TEST_SEED`, select an unused port when another wallet is running,
and run process tests sequentially. Record the actual engine revision; shared
network latency makes a single run unsuitable for fine comparisons.

`tool/kdf_latency_probe.py` measures KDF without Flutter. `--plan-only` inspects
activation batching without starting a wallet; `--kdf` selects the binary.
Check the engine's requirements before disabling P2P for TRON/NFT scenarios.
Use matching P2P settings on both sides of a comparison. A failed RPC must remain
a failure in the report. Never substitute a timeout for an activation result.

Native probes pass KDF configuration through process arguments. Use only an
unfunded test seed; temporary databases and retained diagnostic logs require the
same care as the supplied seed. Do not upload harness wallet databases.

## Browser measurement

Build the pinned release with `FRAME_TIMING_CAPTURE=true` and the four GasFree
defines in [TESTING.md](TESTING.md). `tool/web/bench_serve.py` serves that output;
`tool/web/kdf_web_probe.html` isolates KDF without Flutter.

For a real-app capture: enable Diagnostic Logging, start DevTools Performance
and network recording, log out/in, then download the log. Parse it with
`dart run tool/parse_wallet_load_log.dart <log> --json`. Capture both cold startup
and a warm re-login. Preserve HAR and trace files beside the result, after
reviewing them for wallet data. Diagnostic logging itself adds main-thread work.

Use frame-arrival gaps from `computeFrameGapMetrics` as well as Flutter build
and raster durations. A blocked browser can prevent frames from arriving at all;
fast individual frames do not prove a responsive page. Keep refresh rate and
capture duration with percentiles and worst gaps. Low frame yield can mean idle
time, so it is not an independent jank verdict.

Chrome long-animation-frame attribution helps separate KDF entry points from
Dart code. Its 50 ms floor misses smaller repeated work, it is unavailable on
some browsers, and synchronous Wasm called from Dart is charged to that entry
point. Treat attributed KDF time as a lower bound.

## Reproducible comparisons

`tool/bench_web_jank.sh <label> <runs>` captures repeated login flows;
`--compare <baseline> <candidate>` compares their artifacts. Use a representative
HD wallet, asset count and balances. An unfunded Iguana fixture with a few coins
cannot establish responsiveness for a large HD wallet.

Take at least five samples per arm and compare medians with run-to-run spread.
Include capture-off and idle controls to estimate instrumentation cost. Do not
claim improvements inside the noise band. Inspect fresh artifact timestamps,
recorded failures and the test completion marker as well as process exit status.
Do not drive a measured frame window with `tester.pump`: it manufactures frames;
use the harness's live frame policy and asynchronous waits.

## Toolchain and artifacts

Use the Flutter version in `.fvmrc` for builds and tests. A shader or native-asset
cache generated by another version can fail before application code runs.
Regenerate incompatible build output with the pinned toolchain. Inspect git
diffs after asset builds: transformers can alter lockfiles and bundled coin
pins. Preserve intentional source edits when removing generated churn.

Store raw captures and historical investigation reports outside the release
checkout. Retain regression tests, CI scripts and maintained benchmark baselines.
